## New Foundation Principle

**Cognitive Offloading.** The platform exists to hold what JT and Audra would otherwise have to remember, decide, or repeat. Any action that can be inferred from an action they were already taking should be inferred. Any context that can be carried forward should be carried forward. Memory is a finite resource; the platform spends its own so theirs is freed.

Sits alongside **Surface Principle** (mobile ops / desktop creation) and **Performance Principle** (show first / sync second). Third foundation principle. Applies to JT *and* Audra — user-centric, not JT-centric.

---

## Corollaries (operational rules under Cognitive Offloading)

- **Date-Driven Priority.** Default order across every surface = soonest due, actionable for the current user. Completion sinks. Blocked items don't appear in the priority view. Visual indicator escalates items within N days of release.
- **Decisions Are Binary.** N-way choices consume working memory. Default surfaces narrow to binary or small-N (pair / trio). N expands only inside deliberate escape hatches.
- **Hidden Until Engaged.** Originator escape hatches live behind a deliberate gesture. They do not fight the approver default for screen real estate.
- **Escape Hatch Returns You Home.** Originator output (Claude chat, GenGem) terminates in the same editable element as the default path. Tools generate; the canvas owns.
- **The Schedule Button Is The Verb.** Atomic done = Schedule pressed. Not Save, not Approve, not Done. Schedule is the terminal commit on a slot.
- **Resume By Priority, Not By Cursor.** Content state persists (Canvas_State et al.). Navigation state does not. App opens to what needs doing next, not where the user was last.
- **Action Lives Where Awareness Arrived.** Whether discovered proactively, via SMS, or in-app, the remediation gesture sits at the surface where awareness landed. No surface-switching tax.
- **Use The Channel That Arrives In Your Hand.** Don't optimize the channel for rich content. Optimize for whether it reaches the user. Rich content lives in the app, which the channel deep-links into.

## New Corollary

**Point, Don't Narrate.** When context exists in a system surface (audit log, sheet, file, asset), link to it rather than re-render it. Cognitive offloading is served by reducing distance to ground truth, not by generating prose on top of it.

Surfaced when Audra cut off a "what + why" prose proposal with "Just give me a payload link to click." Sits under **Cognitive Offloading.** Sharper than "Claude should explain" — differentiates platform's role as pointer (default) from generator (last resort).

Pattern observed across the session: every time a Cognitive Offloading concern surfaced, the resolution turned out to be *the platform already holds the context, just expose the pointer.* Not summarize, translate, or assist — point.

## New Operational Principle

**The Slot Is The State.** A slot is filled or empty. Make pulls slot contents at post time. There is no commit moment, no approval state separate from filled, no lock gesture, no cutoff visibility. JT can swap contents until Make reads.

This collapsed an earlier pretzel around hard-vs-soft commits, "approved but not scheduled," cutoff visibility, and lock states.

**Refinement to Schedule Button Is The Verb (Session 1):** Schedule remains JT's intent commit — the icon flips, the slot fills, the episode closes from her POV. The technical lock happens silently at Make's read time. JT sees state, not mechanism.

**Caveat — applies to images, but reels are gated:** *Cannot schedule a reel if revision pending.* Availability state (separate from Status — Status governs lifecycle, Availability governs schedulability) blocks reels with active revision requests from entering slots. Once v2 lands, reel returns to available.

## Episode Revision Workflow — Spec Complete

**Player:** Custom HTML5 player, GCS-served (signed URL + native `<video>`), timestamped comment overlay. Drive `/preview` embed killed earlier (same chrome problem that killed Reels Drive embed).

**Commit gesture:** *Request Revisions* button. Soft commit — Audra's icon flips gold→red (her signal to batch), but JT retains add/delete comment ability until Audra uploads v2. Matches JT's "omg I forgot" work style without forcing exhaustiveness.

**Comment data model:**
- Add and delete only — no edit (eliminates edit-drift class entirely)
- States: Active (normal text, top of list) / Resolved (✓ + strikethrough, demoted bottom) / Deleted (strikethrough only, demoted bottom)
- Sorted by episode timestamp within each section
- Both demoted states are persistent and visible to both parties (JT will forget; Audra needs reference)

**Approve:** Explicit terminal gesture for "no revisions needed." Terminal in-app — late changes go through text/Slack to Audra (honest about how JT actually works).

**Permission gradient:**
- JT: adds + deletes own comments; presses Request Revisions; presses Approve
- Audra: uploads v2 (triggers resolved-checkmarks); cannot edit JT's comments

**Reel review note:** JT will not watch the full episode in one sitting. Comments persist across sittings; Request Revisions is the gesture that says "your turn."

## Reel Revision Workflow — Spec Complete

### State machine
- Star (existing): auto-applied on Request Revisions; manual Star also allowed; unstar allowed (symmetric reversibility)
- Star ≠ schedule gate. Revision pending = schedule gate (Availability = blocked).
- "Edited" pill on card after v2 lands, auto-clears on view

### Trim path (JT-side, self-service)
- JT clicks **Edit Reel** in app → 3-state button:
  - State A (initial): `[Edit Reel]`
  - State B (loading): spinner, "Creating workfile..."
  - State C (linked): green check, "Editor open — linked"
- Workfile saves in shared drive Reels folder (alongside source reel) — your project has direct read access
- JT trims (by transcript — ADHD-friendly) → exports → file lands in **her** `My Drive/Vids Exports/`
- JT clicks **Sync** in app → Sentinel Fairy moves export to shared drive
- Hourly fallback trigger on Sentinel Fairy in case JT forgets Sync

### Workfile capture handshake
- Click on **Edit Reel** fires a 1-min polling loop in your project's GAS
- Match key: **Root-filename match + CreatedTime > click-time + MimeType = Vids workfile**
- Poll interval: 5s / Timeout: 60s
- Found: Asset_Library row updated with `Vids_Workfile_ID`, button → State C
- Not found at timeout: button falls back to `[Retry]` / `[Paste link manually]`

### Sentinel Fairy (separate GAS project, bound to JT's account)
- **Why separate:** project service account can't read JT's My Drive; her bound script can
- **Triggers:** time-based (hourly fallback) + on-demand via web app `doPost()` endpoint called by app's Sync button
- **Logic:** scan Vids Exports folder → find file matching reel root → exponential backoff (30s, 60s, 120s) for render-not-yet-complete → move to shared drive → UrlFetch `doPost` to project's web app → archive older versions
- **Failure mode:** After 3rd attempt, surfaces "Google is still cooking your video. Tap Sync again in a minute." Avoids runaway background process.
- **Deployment:** Execute as JT; access scope TBD (Anyone with link vs. domain-restricted)

### Match logic for new file intake
- Root-filename + timestamp suffix recognition
- Most recent version wins; older trimmed versions archived to `Vids_Archive` subfolder

### Schema collapse — Asset_Library final

```
Asset_Library_ID       (stable, never changes)
Source_Filename        (captured at upload; survives renames; match anchor)
Episode_UID
Asset_Type
GCS_Path / Drive_File_ID  (single pointer; derived from ID where possible)
Version_Number         (integer, increments on upload)
Status                 (processing | available | blocked)
Availability           (available | blocked-by-revision)   ← separate from Status
Starred                (boolean)
Vids_Workfile_ID       (nullable; populated on first edit)
Updated_At
```

No Version_History JSON. No file path juggling. Comments anchor via `Resolved_At_Version` integer.

### Storage layer
- **Interim (Drive):** `Drive.Files.update(fileId, blob)` — replaces bytes, fileId stable. Same fileId → same URL → Make unchanged.
- **Eventual (GCS):** PUT to stable path derived from Asset_Library_ID. Overwrite semantics.
- Same architecture both ways; storage backend is implementation detail.
- Race condition handled by `Status = processing` gating Make reads during upload.

## New Corollaries

**Absence Is A Signal.** When an expected payload is missing from a surface, the empty state itself communicates upstream work to the user. No error, no block, no modal. The gap is the message. Sits under **Cognitive Offloading.**

Surfaced when JT-opens-release-day-email-pre-Filing was probed. The missing assets folder link in the email body tells JT she hasn't finalized assets yet — no platform-side narration required. Generalizable to any case where a payload is expected at a specific time and its absence is itself diagnostic.

**Edit Is A Mode, Not A Default.** Reference surfaces (Episode Card, Guest Brief, etc.) open read-only. Edit is a deliberate gesture — a contextual button (`Edit Contact`, `Edit Description`) that flips the surface into a writable state. Save flips it back and triggers any associated automation (Gemini grammar diff, Herald re-enrichment). Cognitive load stays low; accidental typing is structurally prevented.

**Workspace Persistence.** Each user has exactly one editable copy per reference doc. The copy persists across sessions — no version proliferation, no "which copy was I editing last week." Subsequent edits re-unlock the same workspace rather than forking again.

Both new corollaries sit under **Cognitive Offloading.** Together they replace what would otherwise have been version-control machinery for reference docs.

## New Operational Principles

**Pending Is Derived, Not Stored.** Slot states like "Pending" are computed at render time from the join between a slot recipe table and Asset_Library presence. They are not values in a Status enum. Implications: no schema migration to introduce a Pending state, single source of truth (presence of an available Asset_Library row), and the same logic generalizes across asset types.

**Sibling, Not Sibling Surface.** Non-episode-scoped content that follows the same scheduling pattern lives in the same surface as episode content. The distinction between scoped and unscoped is a data-layer fact (nullable foreign key), not a UI boundary. Resist building parallel surfaces for content that scheduling-wise behaves identically.

Sits under **Cognitive Offloading** (no second mental model for JT to maintain) and **Generic In Name, Specific In Build** (App_Structure v1.2 — don't generalize until forced).
